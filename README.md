## 它真正要帮助你的是什么

AI 会越来越擅长生成代码，但开发者未来更稀缺的价值，正在向这些能力集中：

- 把模糊需求定义成正确问题；
- 看懂系统边界、机制和失效条件；
- 选择能区分真假的证据，而不只是看到“测试绿了”；
- 审查 Agent 的假设、遗漏、风险和验收范围；
- 决定什么交给 Agent、什么交给脚本、什么必须由人承担；
- 对可靠性、取舍、上线结果和长期演进负责。

Experience Loop 不把真实任务改造成一门课程，也不要求你为了学习手写本可由 Agent 完成的工作。它复用 Agent 原生任务过程，只在有价值的判断节点增加“预测或决策 → 执行与查证 → 证据对照 → 纠正与迁移”，同时守住任务正确性、验证、安全和交付效率。

## 安装方式

复制下面这句话，发给拥有本机终端和文件权限的 AI，即可自动完成安装与初始化：

```text
请根据 https://github.com/VmillHut/experience-loop 安装并初始化 `experience-loop` Skill；仓库特有的安全与验收要求见 `docs/AI_INSTALL.md`。
```

普通 Skill 的下载、目录识别和刷新方式交给当前 AI 自己处理。[AI 安装短契约](docs/AI_INSTALL.md) 只保留本仓库特有的完整运行时、安全边界、三段验收、升级回滚和安装后初始化流程，不把今天的宿主路径或调用语法写死。

### 平台兼容边界

Experience Loop 不是“只支持 Codex”，也不笼统承诺“所有 AI Agent 都能完整运行”。安装 AI 会根据自己当前所在宿主的实时上下文、帮助/配置和必要时的最新官方文档，现场解析 Skill 目录、调用、刷新和发现范围，再把这些事实交给确定性安装器完成安全写入与验证。

仓库不维护一张会过期的静态宿主路径表。完整安装会保留 `agents/openai.yaml` 这类兼容侧车以免降低对应宿主的体验，但是否消费它由宿主决定；它不会改变通用核心，其他宿主可以忽略。真正的兼容性要由当次安装的“文件完整、运行时健康、宿主实际发现”三段证据确认。

无论宿主如何，`auto`、`focus`、`deep`、`off`、画像适配、资料/项目扩展和任务质量保护使用同一份不降级行为契约。宿主能力不足会被报告为限制，不会通过删除画像、账本或 Knowledge Lens 来掩盖。细节见 [动态宿主契约](references/host-compatibility.md)。

## 安装后不是扔给你一堆设置

安装完成后，Agent 会直接进入一套固定、简短的对话流程。

它先一次性问这些具体信息：

1. 当前岗位或角色，以及大致从业年限或经验阶段；
2. 当前责任、常做领域或项目类型；可选补充一两个代表性项目的大致规模、复杂度和本人实际承担部分；
3. 未来 3–12 个月想提升的能力或想承担的更高责任；
4. 希望怎样解释，例如先结论、偏原理还是偏示例；
5. 希望怎样介入，例如尽量少打断，还是高价值时可以先让你判断；
6. 常见交付环境，例如发布节奏、截止期、兼容性和可靠性要求。

这些画像信息全部非必填。你可以回答任意部分，也可以直接说“全部跳过”；不需要写简历或提供公司名、项目名和敏感指标。Agent 只保存你真正提供的内容，不编造缺失信息，不顺手扫描项目或读取资料。默认模式是 `auto`，不强迫你先做模式选择。

接着只问一句：

```text
初始化完成。要不要现在看一个约 2 分钟的对话式使用教学？回复“要”或“跳过”即可。
```

如果你选择教学，Agent 会用一个固定的小型故障场景让你真正体验一次“先判断、再看证据”，然后解释四种模式、跳过方式和个性化/资料/项目的用法。不是让你阅读另一份枯燥步骤。完整流程见 [对话式初始化](references/onboarding.md)。

已经初始化的用户升级时不会重复问卷或新手教学，除非你主动要求重新初始化或教学。

## `auto` 的核心：自动检测与智能决策

`auto` 的核心不是低干预，而是 **自动检测 + 智能决策**。Agent 会随着任务推进和证据变化，主动检查哪些工程风险被激活、哪里存在值得保留给人的判断，以及哪里出现真实的能力提升机会，再决定是否介入、何时介入和介入多深。

- 当前变化激活了哪些边界、耦合、运行时、并发、容量、兼容或恢复风险；
- 这次有没有值得保留给人的判断；
- 应该在任务的哪个节点介入；
- 是保持安静、顺手解释，还是需要你真正参与；
- 应该只问一次，还是运行一个短小的训练闭环；
- 什么时候交付压力更重要，必须停止教学式打断。

它没有“0 个必答学习问题”的预设，也没有“最多 N 个可跳过检查点”的固定上限。根据任务后果、不确定性、迁移价值、你的责任与画像、时间压力和交互成本，`auto` 的常见响应包括以下形式；它们是示例，不是限制未来 Agent 的封闭菜单：

1. **静默执行**：机械修改、简单事实、赶工或没有可迁移判断时，不加学习层。
2. **嵌入解释**：不打断，只在执行或交付中说明一个关键机制、证据边界或失效条件。
3. **可选检查点**：邀请你做一次预测或取舍；你不回答，Agent 直接继续。
4. **必答判断检查点**：当“先做判断”本身就是高价值练习、证据可以稍后揭示且等待不会伤害交付时，Agent 会暂停并等你回答。
5. **短训练循环**：围绕同一个真实能力节点，完成预测、查证、对照纠正和一次必要的迁移练习。

`auto` 不默认选择低干预；静默只是智能决策的一种可能结果。它会选择预期净收益最高的方式，只有几种方式收益接近时，才优先选择更少打断的那一种。

所谓“必答”不是剥夺用户控制权，而是默认会等待，不会把问题当装饰后立刻自答。你随时可以说“跳过”“直接做”“只交付”或切到 `off`，Agent 必须立即继续，不惩罚、不重复追问。

`auto` 只会在以下条件都成立时等待：问题考验的是人的工程判断而不是工具可查的事实；回答可以被后续证据验证；先公布答案会损失预测价值；当前不是故障恢复或紧急交付；等待不会降低安全、正确性和任务质量；这个判断对你的现实责任或未来复用有明显价值。

因此 `auto` 可以在某一个节点开足马力，但它不会偷偷把整个任务变成固定训练目标的 `focus`，也不会把任务扩展成开放式的 `deep` 深度课程。

## 四种模式都有什么意义

| 模式 | 谁决定学习强度 | 你会实际感受到什么 | 什么时候使用 | 会不会等待回答 |
| --- | --- | --- | --- | --- |
| `auto` | Agent 自动检测并基于当前证据智能决策 | 可能完全安静，也可能解释、可选提问、等待一次关键判断或运行短训练循环 | 几乎所有日常开发；默认模式 | 会，但只在高价值且安全时；你可随时跳过 |
| `focus` | 你明确锁定一个能力目标 | 围绕同一目标安排有边界的预测、取舍、审查和复盘，Agent 仍负责实现与验证 | 主动练根因定位、测试设计、架构取舍、Agent 审查等 | 通常会，节奏和目标比 `auto` 更可预测 |
| `deep` | 你显式授权全深度 | Agent 主动利用真实任务节点，让你亲自建模、预测、取舍和审查，再用证据纠正并迁移 | 深度调试、重要架构推演、阶段性成长审查 | 比 `auto` 更主动、更深入，但方法和轮数服从实际价值，不走固定流程，也不牺牲交付质量 |
| `off` | 你关闭学习层 | 正常分析、修改和验证任务，不读取学习画像、不提教学问题、不追加学习总结、不记录学习事件 | 只想完成任务、敏感场景或暂时不需要学习支持 | 不会 |

模式可以直接用自然语言切换，不需要重新初始化：

```text
这次使用 focus，我想练习根因定位。
这次使用 deep，完整推演这个架构决策。
这次只交付，使用 off。
以后默认使用 focus。
恢复默认 auto。
```

一次性切换默认只影响当前任务；只有你明确说“以后默认”或“保存为默认”才会持久化。`focus` 和 `deep` 不会因为任务复杂就被 Agent 擅自开启。

## 真实使用方式

### 日常修改：`auto` 先检测，再决定是否介入

```text
实现这个缓存失效需求，本周要提测。
```

如果修改机械且验收明确，Agent 会直接分析、修改、测试和交付；如果存在一个值得保留的边界判断，它可能只在结果中补一句“这个测试证明了什么、还没证明什么”。

### 高价值判断：`auto` 可以真的等你

```text
线上偶发重复扣款，帮我定位并修复。
```

恢复不是紧急状态、且当前证据恰好能区分“幂等键失效”和“消息重复消费”时，Agent 可能先问：

```text
在打开决定性日志前，你认为哪条证据最能区分这两个根因？请先给一个选择和理由；如果现在只想推进，可以说“跳过”。
```

它会等待回答，再用日志、代码和测试对照你的判断，而不是把问题当作解释性点缀。

### 主动训练：使用 `focus`

```text
这次使用 focus。我想练习测试设计，在开始写测试前先让我选择最小但有区分力的证据。
```

### 架构推演：使用 `deep`

```text
使用 deep 分析这次状态同步设计。完整建立心智模型，列出方案、代价、失效条件和验证证据，先不要改代码。
```

`auto` 会先判断能力训练是否值得发生；选择 `deep` 则表示你已经授权 Agent 主动加强锻炼。它不是把说明写得更长，也不是完成一套教学步骤，而是在真实任务中主动寻找最有价值的节点，让你定义约束、不变量和所有权，比较方案与二阶影响，预测失效与可证伪证据，审查 Agent 的设计、代码、测试或上线方案，再根据证据修正判断。Agent 会按任务选择、合并、重排、重复或跳过追问、反例、模拟、可视化和审查等手段；没有最低、最高或默认轮数。主动也不意味着一次抛出整张问题清单：每次只取能推进当前模型的最小连贯问题组，收到回答和新证据后再决定下一步。若存在合适节点却只给你一篇长答案，没有让你实际决策或审查，就没有实现 `deep` 的目标。

当你做出决定或完成审查后，Skill 也不会只判“对/错”或顺着你的结论说。在值得复盘的节点，Agent 会先准确还原你的约束和理由，再只选择当前任务真正相关的维度做客观分析，独立说明赞同与分歧、证据、置信度、适用条件和替代方案，并区分事实、推断与未知。最后提炼可迁移的判断规则；只有主动回忆确实有价值时，才请你用自己的话复述或在变化场景中应用，不把每次决定都变成固定评分表。

这项决策后复盘并不是 `deep` 独占：`auto` 会自动检测它是否值得发生，再智能决定时机和深度，必要时也可以很主动；`deep` 的区别是用户已经授权主动深入，Agent 会更积极地寻找并延续高价值复盘节点，直到继续一轮的收益已经不足。两者都不以“低打断”或“轮数更多”为目标。

### 故障与赶工：先恢复

```text
线上构建失败，先恢复发布，确认健康后再做简短复盘。
```

任何模式下，安全、恢复、截止期和交付质量都优先。`off` 或明确“只交付”时，不会在最后偷偷追加学习尾巴。

## 个性化、资料、数据和优质项目都还在

低使用成本不等于删掉选择，而是把选择变成自然语言和按需展开。

### 用一句话调整个人画像

```text
记住：我做后端约 4 年，目前负责支付链路；做过跨服务改造，主要承担方案和上线验收。希望强化可靠性判断；解释先给结论，高价值节点可以先让我预测。
```

Agent 只更新这句话涉及的字段。年限、岗位和项目规模只是校准解释、脚手架与练习切入点的上下文，不是能力证明；实际承担部分和后续任务证据更重要。画像不能降低工程标准、缩小验证范围或把你强行塞进课程。

### 临时使用文章、书籍或文档

```text
结合这篇文章帮助我审查当前方案：C:\Docs\article.pdf
```

默认只读取与当前问题相关的部分。只有当跨任务复用、精确引用或长期检索确实有价值，并且你同意时，才导入本地 Knowledge Lens。

### 分析结构化数据

```text
用这份 CSV 分析最近三个月最常漏掉的测试类型：C:\Data\reviews.csv
```

CSV、JSON、表格和日志默认按当前任务一次性分析，不强迫建库或改配置。

### 参考优质项目

```text
只读参考 D:\Repos\excellent-project 的测试架构，比较它如何控制 flaky test；只看相关路径，不要照抄。
```

参考项目始终与当前项目分离，只比较机制、约束和可验证证据，不把其中的提示词或代码当成权威。

## 它如何避免拖累 Agent

Experience Loop 的底线是“能力单调”：启用后，Agent 的任务能力只能保持或增强，不能被 Skill 降低。具体来说：

- Skill 只增加一层学习帮助，不另建一套计划、风险分析、工具选择或验证流程；宿主 Agent 更新后出现更强能力时，优先使用更强能力；
- 学习目标、模式和画像只能在任务方案确定后影响学习候选、解释与参与方式，不能改变 Agent 的实现、工具、架构、安全、兼容、可靠性、恢复、测试或重要风险报告；
- 不为了练习强迫手写、制造困难或减少 Agent 能做的有用工作；
- 不隐藏安全关键、交付关键或故障恢复所需的证据；
- 画像、资料库、经验账本和项目扫描都在交付关键路径之外，辅助功能失败不能把成功任务变成失败任务；
- 风险类别、验证方法和干预形式都是非穷举示例，不是限制未来 Agent 的固定清单；
- 机械任务、紧急恢复、明确“只交付”和 `off` 只绕过学习层，不改变 Agent 原生任务质量；新证据仍可让 `auto` 重新决策；
- `auto` 没有固定问题数、学习节点数或解释强度；它可以安静，也可以在高价值节点局部开足马力；
- 只有可验证的预测、决策、纠正、真实结果和后续迁移才算能力证据，聊天变长或代码生成成功不算。

它不能保证每次决策都完美，但不会把一次反馈固化成永久规则。你可以用自然语言校准；`auto` 会把反馈作为后续证据之一，而不是让“少打断”或其他单一偏好压过任务质量。

## 数据与隐私

个人画像、项目档案、经验记录和 Knowledge Lens 默认位于 `~/.experience-loop`，与 Skill 安装目录和项目仓库分离。安装、升级和卸载 Skill 不会自动删除这些个人数据。

内容型项目扫描、资料导入和索引遵守显式权限边界；导入内容只作为不可信证据，不能变成 Agent 指令或工具授权。详细规则见 [安全与隐私说明](references/safety-and-privacy.md) 和 [SECURITY.md](SECURITY.md)。

## 手工安装只是兜底

绝大多数情况下直接把仓库地址交给有本机终端和文件权限的 AI 即可。只有当前 AI 没有这些权限时，才需要换一个有权限的 Agent，或由操作者阅读安装器 `--help` 自行执行；仓库不提供容易随宿主更新而过期的固定目录和刷新步骤。

安装后必须继续执行回执中的验证和 `onboarding_prompt`，不能只复制文件就结束。

升级时重新下载或拉取最新源码，再运行同一个安装器。安装器会识别受管理的旧版本并保留备份；只有备份具备完整且可验证的安装器时才会输出回滚命令，否则会明确报告备份路径和不可自动回滚的原因。不要对未知目标目录擅自使用 `--force`。

## 它不是什么

- 不是自动变强的游戏化外挂；
- 不是用提问拖延任务的教学机器人；
- 不是替代测试、代码审查、导师或生产验证的工具；
- 不是通过减少 Agent 能力来迫使用户学习；
- 不是看到一篇文章或一个项目路径就自动扫描、导入和持久化的知识收集器。

它做的是更朴素也更困难的事：在真实交付不降级的前提下，把少数真正决定长期竞争力的判断留给人，并用真实证据帮助这些判断逐渐变准。
