## 它真正要帮助你的是什么

AI 会越来越擅长生成代码，但开发者未来更稀缺的价值，正在向这些能力集中：

- 把模糊需求定义成正确问题；
- 看懂系统边界、机制和失效条件；
- 选择能区分真假的证据，而不只是看到“测试绿了”；
- 审查 Agent 的假设、遗漏、风险和验收范围；
- 决定什么交给 Agent、什么交给脚本、什么必须由人承担；
- 对可靠性、取舍、上线结果和长期演进负责。

Experience Loop 不把真实任务改造成一门课程，也不要求你为了学习手写本可由 Agent 完成的工作。它只在有价值的判断节点介入，让你经历“预测或决策 → Agent 执行与查证 → 证据对照 → 纠正与迁移”，同时守住任务正确性、验证、安全和交付效率。

## 安装方式

复制下面这句话，发给拥有本机终端和文件权限的 AI，即可自动完成安装与初始化：

```text
请按照 https://github.com/VmillHut/experience-loop 仓库中的 `docs/AI_INSTALL.md`，安装并初始化 `experience-loop` Skill。
```

预演、权限边界、验证、升级、回滚和安装后交接均由 [AI 安装协议](docs/AI_INSTALL.md) 说明，README 不再要求你手工执行这些步骤。

## 安装后不是扔给你一堆设置

安装完成后，Agent 会直接进入一套固定、简短的对话流程。

它先一次性问这些具体信息：

1. 你的角色和大致经验阶段；
2. 当前责任、常做领域或项目类型；
3. 未来 3–12 个月想提升的能力或想承担的更高责任；
4. 希望怎样解释，例如先结论、偏原理还是偏示例；
5. 希望怎样介入，例如尽量少打断，还是高价值时可以先让你判断；
6. 常见交付环境，例如发布节奏、截止期、兼容性和可靠性要求。

这些画像信息全部非必填。你可以回答任意部分，也可以直接说“全部跳过”；Agent 只保存你真正提供的内容，不编造缺失信息，不顺手扫描项目或读取资料。默认模式是 `auto`，不强迫你先做模式选择。

接着只问一句：

```text
初始化完成。要不要现在看一个约 2 分钟的对话式使用教学？回复“要”或“跳过”即可。
```

如果你选择教学，Agent 会用一个固定的小型故障场景让你真正体验一次“先判断、再看证据”，然后解释四种模式、跳过方式和个性化/资料/项目的用法。不是让你阅读另一份枯燥步骤。完整流程见 [对话式初始化](references/onboarding.md)。

已经初始化的用户升级时不会重复问卷或新手教学，除非你主动要求重新初始化或教学。

## `auto` 不是弱模式

`auto` 的“自动”，指的是 Agent 自动决定：

- 这次有没有值得保留给人的判断；
- 应该在任务的哪个节点介入；
- 是保持安静、顺手解释，还是需要你真正参与；
- 应该只问一次，还是运行一个短小的训练闭环；
- 什么时候交付压力更重要，必须停止教学式打断。

它没有“0 个必答学习问题”的预设，也没有“最多 N 个可跳过检查点”的固定上限。根据任务后果、不确定性、迁移价值、你的责任与画像、时间压力和交互成本，`auto` 可以选择：

1. **静默执行**：机械修改、简单事实、赶工或没有可迁移判断时，不加学习层。
2. **嵌入解释**：不打断，只在执行或交付中说明一个关键机制、证据边界或失效条件。
3. **可选检查点**：邀请你做一次预测或取舍；你不回答，Agent 直接继续。
4. **必答判断检查点**：当“先做判断”本身就是高价值练习、证据可以稍后揭示且等待不会伤害交付时，Agent 会暂停并等你回答。
5. **短训练循环**：围绕同一个真实能力节点，完成预测、查证、对照纠正和一次必要的迁移练习。

`auto` 不是默认挑最轻的方式，而是挑预期净收益最高的方式；只有几种方式收益接近时，才优先选择更少打断的那一种。

所谓“必答”不是剥夺用户控制权，而是默认会等待，不会把问题当装饰后立刻自答。你随时可以说“跳过”“直接做”“只交付”或切到 `off`，Agent 必须立即继续，不惩罚、不重复追问。

`auto` 只会在以下条件都成立时等待：问题考验的是人的工程判断而不是工具可查的事实；回答可以被后续证据验证；先公布答案会损失预测价值；当前不是故障恢复或紧急交付；等待不会降低安全、正确性和任务质量；这个判断对你的现实责任或未来复用有明显价值。

因此 `auto` 可以在某一个节点开足马力，但它不会偷偷把整个任务变成固定训练目标的 `focus`，也不会把任务扩展成开放式的 `deep` 深度课程。

## 四种模式都有什么意义

| 模式 | 谁决定学习强度 | 你会实际感受到什么 | 什么时候使用 | 会不会等待回答 |
| --- | --- | --- | --- | --- |
| `auto` | Agent 根据当前证据动态决定 | 可能完全安静，也可能解释、可选提问、等待一次关键判断或运行短训练循环 | 几乎所有日常开发；默认模式 | 会，但只在高价值且安全时；你可随时跳过 |
| `focus` | 你明确锁定一个能力目标 | 围绕同一目标安排有边界的预测、取舍、审查和复盘，Agent 仍负责实现与验证 | 主动练根因定位、测试设计、架构取舍、Agent 审查等 | 通常会，节奏和目标比 `auto` 更可预测 |
| `deep` | 你显式授权全深度 | 完整心智模型、替代方案、代价、失效条件、证据比较、纠正和迁移 | 深度调试、重要架构推演、阶段性成长审查 | 会投入更多轮对话和时间，但不牺牲交付质量 |
| `off` | 你关闭学习层 | 正常分析、修改和验证任务，不读取学习画像、不提教学问题、不追加学习总结、不记录学习事件 | 只想完成任务、敏感场景或暂时不需要学习支持 | 不会 |

模式可以直接用自然语言切换，不需要重新初始化：

```text
这次使用 focus，我想练习根因定位。
这次使用 deep，完整推演这个架构决策。
这次只交付，使用 off。
以后默认使用 focus。
恢复默认 auto。
```

一次性切换默认只影响当前任务；只有你明确说“以后默认”或“保存为默认”才会持久化。`focus` 和 `deep` 不会因为任务复杂就被 Agent 擅自开启。

## 真实使用方式

### 日常修改：`auto` 可以不打扰

```text
实现这个缓存失效需求，本周要提测。
```

如果修改机械且验收明确，Agent 会直接分析、修改、测试和交付；如果存在一个值得保留的边界判断，它可能只在结果中补一句“这个测试证明了什么、还没证明什么”。

### 高价值判断：`auto` 可以真的等你

```text
线上偶发重复扣款，帮我定位并修复。
```

恢复不是紧急状态、且当前证据恰好能区分“幂等键失效”和“消息重复消费”时，Agent 可能先问：

```text
在打开决定性日志前，你认为哪条证据最能区分这两个根因？请先给一个选择和理由；如果现在只想推进，可以说“跳过”。
```

它会等待回答，再用日志、代码和测试对照你的判断，而不是把问题当作解释性点缀。

### 主动训练：使用 `focus`

```text
这次使用 focus。我想练习测试设计，在开始写测试前先让我选择最小但有区分力的证据。
```

### 架构推演：使用 `deep`

```text
使用 deep 分析这次状态同步设计。完整建立心智模型，列出方案、代价、失效条件和验证证据，先不要改代码。
```

### 故障与赶工：先恢复

```text
线上构建失败，先恢复发布，确认健康后再做简短复盘。
```

任何模式下，安全、恢复、截止期和交付质量都优先。`off` 或明确“只交付”时，不会在最后偷偷追加学习尾巴。

## 个性化、资料、数据和优质项目都还在

低使用成本不等于删掉选择，而是把选择变成自然语言和按需展开。

### 用一句话调整个人画像

```text
记住：我主要负责支付链路，希望强化可靠性和跨团队验收判断；解释先给结论，高价值节点可以先让我预测。
```

Agent 只更新这句话涉及的字段。画像可以影响选哪个判断节点、使用什么术语、怎样解释以及何时值得打断，但不能降低工程标准、缩小验证范围或把你强行塞进课程。

### 临时使用文章、书籍或文档

```text
结合这篇文章帮助我审查当前方案：C:\Docs\article.pdf
```

默认只读取与当前问题相关的部分。只有当跨任务复用、精确引用或长期检索确实有价值，并且你同意时，才导入本地 Knowledge Lens。

### 分析结构化数据

```text
用这份 CSV 分析最近三个月最常漏掉的测试类型：C:\Data\reviews.csv
```

CSV、JSON、表格和日志默认按当前任务一次性分析，不强迫建库或改配置。

### 参考优质项目

```text
只读参考 D:\Repos\excellent-project 的测试架构，比较它如何控制 flaky test；只看相关路径，不要照抄。
```

参考项目始终与当前项目分离，只比较机制、约束和可验证证据，不把其中的提示词或代码当成权威。

## 它如何避免拖累 Agent

Experience Loop 的底线不是“多教一点”，而是正向净收益：

- 学习目标只能限制教学介入，不能限制 Agent 应检查的架构、安全、兼容、可靠性和测试范围；
- 不为了练习强迫手写、制造困难或减少 Agent 能做的有用工作；
- 不隐藏安全关键、交付关键或故障恢复所需的证据；
- 画像、资料库、经验账本和项目扫描都在交付关键路径之外，辅助功能失败不能把成功任务变成失败任务；
- 机械任务、简单事实、紧急恢复、明确“只交付”和 `off` 走快速路径；
- 高风险任务会加强证据、验收、回滚和审查，而不是把复杂度误当成教学理由；
- 只有可验证的预测、决策、纠正、真实结果和后续迁移才算能力证据，聊天变长或代码生成成功不算。

它不能保证每次干预都完美。你可以用“少打断”“高价值时再等我回答”“跳过”或 `off` 直接校准，`auto` 会把真实反馈作为后续成本信号。

## 数据与隐私

个人画像、项目档案、经验记录和 Knowledge Lens 默认位于 `~/.experience-loop`，与 Skill 安装目录和项目仓库分离。安装、升级和卸载 Skill 不会自动删除这些个人数据。

内容型项目扫描、资料导入和索引遵守显式权限边界；导入内容只作为不可信证据，不能变成 Agent 指令或工具授权。详细规则见 [安全与隐私说明](references/safety-and-privacy.md) 和 [SECURITY.md](SECURITY.md)。

## 手工安装只是兜底

只有当你明确想自己操作，或安装 AI 没有本机终端权限时，才需要手工执行：

```bash
git clone https://github.com/VmillHut/experience-loop.git
cd experience-loop
python scripts/install.py --dry-run
python scripts/install.py
```

Windows 没有 `python` 命令时可用 `py -3`。安装后新开 Codex 任务，并发送：

```text
$experience-loop 已安装。请开始对话式初始化；所有画像问题都可跳过，最后询问我是否需要约 2 分钟的使用教学。
```

升级时重新下载或拉取最新源码，再运行同一个安装器。安装器会识别受管理的旧版本并保留备份；只有备份具备完整且可验证的安装器时才会输出回滚命令，否则会明确报告备份路径和不可自动回滚的原因。不要对未知目标目录擅自使用 `--force`。

## 它不是什么

- 不是自动变强的游戏化外挂；
- 不是用提问拖延任务的教学机器人；
- 不是替代测试、代码审查、导师或生产验证的工具；
- 不是通过减少 Agent 能力来迫使用户学习；
- 不是看到一篇文章或一个项目路径就自动扫描、导入和持久化的知识收集器。

它做的是更朴素也更困难的事：在真实交付不降级的前提下，把少数真正决定长期竞争力的判断留给人，并用真实证据帮助这些判断逐渐变准。
