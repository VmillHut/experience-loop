# Experience Loop：给安装 AI 的短契约

用户只需发送：

```text
请根据 https://github.com/VmillHut/experience-loop 安装并初始化 `experience-loop` Skill；仓库特有的安全与验收要求见 `docs/AI_INSTALL.md`。
```

常规的下载、宿主识别、Skill 目录定位、命令选择和刷新方式由当前 AI 自行处理。本文件不重复通用安装教程，只说明这个仓库特有、不能靠猜的边界。

## 先动态解析宿主，不依赖静态表

结合当前会话、宿主自身帮助/配置、已有 Skill 注册表，并在需要时查阅当前官方文档，确定现在有效的目标目录、作用域、调用方式、刷新方式、所有可能的发现根目录和共享该目录的宿主。

把这些事实传给仓库安装器；具体参数以 `python scripts/install.py --help` 为准。目录、调用语法和刷新方式都可能随宿主更新，因此仓库不把它们写死。证据不充分就停止说明，不要因机器上装有某个 CLI 而猜测当前宿主，也不要同时写入多个 Agent。

不要把宿主目录、安装参数或刷新方式转交给用户选择；当前上下文足够时由安装 AI 自行处理。只有无法可靠确定且继续猜测会带来风险时，才停止并明确说明“尚未安装”以及缺少什么证据。

## 这个仓库真正需要额外保证的事

1. **完整核心**：安装完整 `SKILL.md`、references、scripts、vendor 和运行时资源。不得删掉画像、账本、Knowledge Lens 或模式能力后降级成提示词副本。
2. **事务安全**：所有写入必须使用仓库安装器完成预演、完整性校验、暂存、托管备份和原子替换；无法使用就报告“未安装”。未知现有目录不得静默 `--force`。
3. **三段验收**：分别验证文件安装、从已安装副本运行 `version`/`mode`/`status`，以及当前宿主实际发现或调用该 Skill。三者不能互相冒充。
4. **真实回滚**：只使用安装回执给出的备份与回滚信息；`rollback_available` 为假时报告 `rollback_note`，不要自行执行不完整备份里的脚本。
5. **状态隔离**：个人画像、项目画像、经验和知识库默认在 `~/.experience-loop`，不属于 Skill 安装目录。安装、升级和卸载不得顺带删除它们。
6. **首装与升级不同**：仅首次未初始化时进入 `references/onboarding.md`；升级保留现有画像，不重复问卷或教学，除非用户要求。
7. **不伪造兼容**：宿主发现或 Python 运行时无法验证时，准确报告限制。不要用静默降级伪造成功。

不可自由发挥的安全顺序只有四步：确认源码远端正是本仓库并记录 commit/dirty 状态；用完整宿主契约运行 `--dry-run --json`；确认无 blocker 后以完全相同的契约正式安装；再做文件、运行时和宿主发现三段验收。不得用手工复制或远程脚本管道替代。

## 安装没有顺带授权这些操作

- 修改全局或项目 Agent 指令、系统提示词、hooks、编辑器配置或其他 Skill；
- 扫描项目、读取用户文章/数据、建立 Knowledge Lens 索引；
- 上传代码、画像或资料，启用外部服务或增加工具权限；
- 删除个人数据、旧备份、仓库或未知目录；
- 使用不可预先审阅的远程脚本管道。

共享发现目录、覆盖未知目录、可选全局路由器和任何额外权限都要单独展示影响并取得同意。

## 安装后必须拉起初始化与后续流程

这不是宿主安装教程，而是 Experience Loop 自身的首次使用与升级契约；安装 AI 必须完成，或在当前会话无法发现新 Skill 时准确交接给刷新后的会话。

安装不能停在“文件已经复制”。按以下状态机完成交接：

1. 从安装回执的 `command_argv` 运行已安装副本的 `version`、`mode` 和 `status`。
2. 若 `status` 表明已有初始化状态，视为升级：保留画像和默认模式，不重复问卷与教学，直接完成健康验证。
3. 若尚未初始化，先验证当前宿主确实发现了该 Skill，再把回执中的 `onboarding_prompt` 发送给当前或刷新后的会话。
4. 按 `references/onboarding.md` 一次性询问具体画像；所有字段都可选，用户可回答任意部分或“全部跳过”。只保存实际回答，不编造缺失信息；初始化不扫描项目、不读取资料、不强迫选择模式。
5. 初始化完成后只问一次是否需要约 2 分钟的对话式教学。同意则运行固定互动示例；跳过则结束，不追加配置步骤。
6. 初始化写入后以相同的数据目录上下文运行 `doctor` 和再次 `status`，确认健康与 `initialized`；若用户显式指定过 `--home`，后续命令必须复用。失败就报告真实错误，不把对话完成当作状态成功。

能自动继续就不要要求用户操作。若宿主刷新确实需要用户动作，最终只给一个当前必要的 `next_action`，不要给路径、命令和模式菜单；刷新后的会话应从上述状态机继续，而不是重新开始安装。

最终只需向用户说明：源码/版本、目标与受影响宿主、文件/运行时/发现三段结果、备份与回滚、初始化状态和真实限制。若当前 AI 没有终端或文件权限，明确说“未执行安装”，不要把阅读文档当作安装完成。
